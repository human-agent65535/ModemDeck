# ModemDeck iOS

Universal SwiftUI client for iPhone and iPad. The app uses the same authenticated
ModemDeck API as Web, while Keychain pairing, APNs, PushKit, CallKit, and WebRTC
call audio remain native platform services.

## UAT milestone

- Mirrors the Web client's light, flat communication layout: compact iPhones
  use the seven-item bottom navigation with an elevated Dial button, while
  regular-width iPads use the same 92-point icon rail as the Web workspace.
- Implements Home, Contacts, Messages, Dialer, Call History, Recordings, and
  Settings directly in SwiftUI; no Web bundle is packaged in the app target.
- Scans the one-time pairing QR code generated by the Web settings screen, with
  manual JSON paste as a fallback.
- Keeps the server address and token in the iOS Keychain.
- Sends API calls through URLSession with Bearer authentication and explicit
  request deadlines.
- Keeps cached history readable during service outages. Foreground recovery
  probes back off from one to thirty seconds, coalesce concurrent refreshes,
  and retry immediately on a restored network path or app activation. SMS,
  call, and other write requests are never replayed automatically.
- Home is a quick view of compact line cards and recent activity, sharing
  message, call, recording, and contact stores with the dedicated pages.
  Native swipe actions and copy/action menus remain available; search,
  filters, and bulk management stay in the dedicated pages. iPad keeps the
  activity list beside its selected detail.
- Imports the device address book from **Settings → Contacts** after native
  Contacts permission and an explicit import confirmation.
- Shows the packaged iOS marketing/build version and local device information
  in About instead of the server application version.
- Registers standard APNs and VoIP PushKit tokens after pairing and stores them
  through the authenticated `/api/v1/mobile/push` endpoint.
- Uses CallKit as the owner for incoming and outgoing calls, answer,
  reject/hang-up, mute, and DTMF, while an audio-only WebRTC peer carries sound
  through the existing call media and lease APIs. The in-app native call surface
  also exposes mute, keypad, recording, and hang-up after CallKit is hidden.
- Presents server-originated synthetic test calls in CallKit and mirrors their
  live state in the in-app call surface. After answer, an audible local test
  tone verifies the CallKit output route without creating a modem call, call
  record, call lease, or WebRTC session.
- Requires ModemDeck v1.12.0 or newer plus matching Apple provider credentials
  on the server before remote delivery is enabled. Debug builds installed
  directly on a device use APNs sandbox; the distributed TestFlight app uses
  APNs production. The server routes each token to the matching APNs host.

## Commands

```sh
# Build the simulator application with Xcode Beta.
npm run build:ios

# Rebuild, install, and launch on the preferred Pro Max simulator.
npm run run:ios:iphone

# Rebuild, install, and launch on the preferred iPad Pro simulator.
npm run run:ios:ipad
```

On first launch, scan the QR code shown by Web **Settings → Pairing**.
Manual JSON paste remains available for a simulator or a device without camera
access. Read-only validation is safe; sending an SMS or placing a call is a real
external action and must be performed deliberately during UAT.

The older Capacitor preview builder remains temporarily available through
`npm run sync:ios` while migration tests are retained, but it is no longer the
app target's UI source and its generated `public` directory is not packaged.

## APNs and PushKit deployment

The iOS target requests the `remote-notification` and `voip` background modes,
registers both token types, and sends the hexadecimal token values only after a
pairing credential has been saved. The server validates and stores the tokens
on the pairing credential, replacing them when the user rotates the pairing.

The tracked Xcode configuration uses the neutral `com.example.modemdeck`
identifier and contains no personal signing identity. Local physical-device and
TestFlight builds load `ios/LocalSigning.xcconfig`, which is ignored by Git, to
provide the Apple Team and private bundle identifier. The Apple provider must
be configured on the server with the Apple Team ID, Key ID, `.p8` signing key,
and a topic matching the archive's `PRODUCT_BUNDLE_IDENTIFIER` before it can
send SMS or incoming-call payloads.
VoIP payloads should contain a `modemdeck_call` object with `call_id`, `uuid`,
`remote_number`, and optional `display_name`; PushKit then reports that call to
CallKit and the native owner uses the existing call, lease, and media APIs.
Setting `test_call` to `true` keeps the event entirely local: answering plays a
short generated tone and the call automatically ends after thirty seconds.

## Read-only simulator smoke test

`scripts/uat-mock-server.mjs` provides a loopback HTTPS endpoint that accepts a
disposable pairing token and serves privacy-safe synthetic lines, contacts,
messages, calls, and recordings. Every write is rejected, so it can validate
onboarding, Keychain, native Bearer requests, and adaptive layouts without
touching a modem.

```sh
mkdir -p DerivedData/uat-mock
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout DerivedData/uat-mock/server-key.pem \
  -out DerivedData/uat-mock/server-cert.pem -days 1 \
  -subj '/CN=ModemDeck iOS UAT' \
  -addext 'subjectAltName=IP:127.0.0.1,DNS:localhost' \
  -addext 'basicConstraints=critical,CA:TRUE' \
  -addext 'keyUsage=critical,keyCertSign,digitalSignature,keyEncipherment' \
  -addext 'extendedKeyUsage=serverAuth'

DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun simctl keychain booted add-root-cert \
  DerivedData/uat-mock/server-cert.pem

MODEMDECK_UAT_TOKEN=md_ios_AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA \
  node scripts/uat-mock-server.mjs \
  --cert DerivedData/uat-mock/server-cert.pem \
  --key DerivedData/uat-mock/server-key.pem
```

Pair with `https://127.0.0.1:8443` and the disposable token above. The mock
request log is the transport evidence; it never prints the token.

For simulator-only visual review, the Debug build can inject that disposable
credential before the SwiftUI root loads:

```sh
SIMCTL_CHILD_MODEMDECK_UAT_MODE=1 \
SIMCTL_CHILD_MODEMDECK_UAT_SERVER_URL=https://127.0.0.1:8443 \
SIMCTL_CHILD_MODEMDECK_UAT_TOKEN="$MODEMDECK_UAT_TOKEN" \
  npm run run:ios:iphone
```

Set `SIMCTL_CHILD_MODEMDECK_UAT_CALL_STATE=active` as well to render the native
in-call surface without creating a server call. Add
`SIMCTL_CHILD_MODEMDECK_UAT_CALL_KEYPAD=1` to open its DTMF keypad immediately
for layout review. The UAT-only injection is compiled out of Release builds.

For direct review, set `SIMCTL_CHILD_MODEMDECK_UAT_INITIAL_SECTION` to `home`,
`contacts`, `messages`, `dial`, `calls`, `recordings`, or `settings`.

The injection is compiled only under `DEBUG`; Release builds always require
normal QR pairing and Keychain confirmation.

## Automated native regression tests

`npm test` runs the existing source/runtime checks and, on macOS, compiles the
actual connection-recovery owner with a deterministic Swift behavior harness.
The harness covers capped backoff, concurrent refreshes, network/resume
recovery, cancellation, and revoked-session shutdown without a live service.

The simulator-only **App-UAT** scheme adds XCTest interaction tests for Home,
shared read/favorite state, delete confirmation and recording cleanup,
foreground refresh, edge-back navigation, and automatic recovery with cached
history. No UI-test code or fixture credential is included in the app target.

Use a disposable Pro Max or iPad Pro simulator running iOS 17 or later, as
required by Xcode Beta's UI-test framework; the app's deployment target is
unchanged. Generate the temporary TLS
certificate as above and trust it on that simulator only, using its explicit
UUID instead of `booted`. Start this opt-in fixture server in another terminal:

```sh
MODEMDECK_UAT_TOKEN=md_ios_AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA \
  node scripts/uat-mock-server.mjs --mutable --port 18943 \
  --cert DerivedData/uat-mock/server-cert.pem \
  --key DerivedData/uat-mock/server-key.pem
```

`--mutable` only changes synthetic in-memory fixtures on loopback. It allows
read/favorite/delete tests and simulated service outages; it cannot send an
SMS, place a call, or proxy requests to a real server. Without this flag the
fixture server remains read-only. Each UI test resets the fixture; run devices
sequentially to avoid resetting another test's state.

```sh
UAT_SIMULATOR_ID="DISPOSABLE_SIMULATOR_UUID"
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcrun simctl keychain "$UAT_SIMULATOR_ID" add-root-cert \
  DerivedData/uat-mock/server-cert.pem

DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  xcodebuild -project ios/App/App.xcodeproj -scheme App-UAT \
  -configuration Debug -sdk iphonesimulator \
  -destination "id=$UAT_SIMULATOR_ID" -derivedDataPath DerivedData \
  -onlyUsePackageVersionsFromResolvedFile \
  -disableAutomaticPackageResolution -skipPackageUpdates \
  -parallel-testing-enabled NO \
  -resultBundlePath "DerivedData/uat-ui-$(date +%Y%m%d-%H%M%S).xcresult" test
```

Inspect the retained screenshot attachments, including iPad portrait and
landscape, as well as the assertions. Stop the fixture server and shut down
the disposable simulators after testing. These checks are not evidence of
physical-device radio changes, background push delivery, or call audio.

## Foreground UAT acceptance

1. Confirm the public Cloudflare health endpoint and iOS-enabled API build are
   healthy, then create a fresh pairing in Web **Settings → Pairing**.
2. Pair on iPhone and iPad and verify Home, Messages, Calls, Contacts,
   Recordings, and Settings using read-only data first.
3. Confirm app relaunch restores the Keychain pairing and foreground refreshes
   current server data.
4. With a designated test line and destination, send one labelled SMS and
   verify delivery plus message-event reconciliation.
5. With the same explicit test authorization, place one call, verify two-way
   audio, mute, DTMF, hangup, history, and recording playback as applicable.
6. Revoke the iOS pairing in Web and verify the app returns to onboarding on
   the next request.
